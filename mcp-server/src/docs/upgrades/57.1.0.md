# 57.1.0

Terreno packages move in lockstep. Bump every `@terreno/*` dependency to `57.1.0`, then:

```bash
bun add @terreno/ui @terreno/api @terreno/rtk
# optional
bun add @terreno/syncdb @terreno/admin-frontend @terreno/comms
```

- `bun run compile` and `bun run lint` at the app root
- `cd <your frontend> && bun run sdk` after any `@terreno/api` route or model surface change

This is a minor on the Expo SDK 57 line. No Expo upgrade is required if you are already on `57.0.0`.

## `@terreno/rtk` data sync is deprecated

Collection CRUD through `@terreno/rtk` is deprecated (first called out for `56.0.0`). The package still publishes through this major and remains required for the OpenAPI SDK, Better Auth Redux, feature flags, and sockets. It will not ship in the next major.

Migrate collection screens to [`@terreno/syncdb`](../../../docs/reference/syncdb.md) using [migrate-rtk-to-syncdb.md](../../../docs/how-to/migrate-rtk-to-syncdb.md). New apps from `terreno_bootstrap_app` now scaffold Better Auth + syncdb instead of JWT `generateAuthSlice`.

Typed collection hooks can be generated with the `terreno-syncdb-codegen` bin of `@terreno/syncdb` (not a separate package):

```bash
bunx terreno-syncdb-codegen --schema http://localhost:4000/openapi.json --out store/syncDbSdk.ts
```

## RBAC (`@terreno/api`)

RBAC is opt-in. If you do not call `createAccess` / `accessControl`, skip this section except the `RbacRoleModel` singleton removal if you imported those names.

### Register models on your connection

Importing `@terreno/api` no longer registers `RbacRole` / `RbacAudit` on the default mongoose connection. The `RbacRoleModel` / `RbacAuditModel` **value** singletons are gone; the `RbacRoleModel` **type** remains.

```typescript
// Before
import {RbacRoleModel} from "@terreno/api";
await RbacRoleModel.find();

// After
import {createAccess, createRbacRoleModel} from "@terreno/api";
import mongoose from "mongoose";

const access = createAccess({
  connection: mongoose.connection,
  statements: appStatements,
  userModel: User,
});
// or, in scripts/tests only:
const RbacRole = createRbacRoleModel(mongoose.connection);
```

See `example-backend/src/access.ts`.

### Fail closed

- `createView: "deny"` and unknown field-view names deny instead of granting a full mask.
- Nested omits clone documents; write masks honor dotted paths; bulk create and array mutations use the same write mask as single-document writes.
- Admin CRUD for a resource missing from statements fails closed (list/read, search, and writes).
- Permission-source refresh with `staleOnFailure: "deny"` (default) keeps last-cached **deny** grants; additive `roles` / `permissions` from that source are omitted.

If a previously unknown view name silently allowed a full mask, tighten statements or name the view.

### AdminApp + `admin:access`

`admin:access` is no longer enough for model CRUD. Each resource needs its list/read/create/update/delete actions. Framework statements now include `featureFlag`, `consentForm`, and `consentResponse`.

| Action | Required permission |
| --- | --- |
| Admin model CRUD | Resource verb **and** `admin:access` |
| `POST /admin/background-tasks` | `admin:runScripts` |
| Version-config GET / PUT | `configuration:read` / `configuration:update` |
| Change User `admin` (RBAC on) | `rbac:assignRoles` **and** an actor who already has the legacy admin flag (`rbac:manageRoles` is not a substitute) |
| Assign / unassign roles | Actor already holds the target user's current permissions |

The seeded `auditor` role no longer receives `admin:access` from read-only expansion.

Without RBAC, admin User CRUD may still set `admin`. With RBAC, `roles` go through `RoleManager.assign`. Echoed unchanged `admin` values on create/update are allowed.

### Privilege fields are stripped on self-service writes

Signup, `PATCH /auth/me`, and ordinary User modelRouter / sync / MCP writes drop `admin`, `roles`, and `organizationIds`. Change organization membership through a privileged server path, not self-service.

`example-backend` `backfillAdmins` is a dry run unless `RBAC_BACKFILL_ADMINS=true`. Live production admin script resets require `ALLOW_ADMIN_DB_RESET=true`.

### Custom `modelRouter` actions

`runActionPermissions` **combines** legacy `action.permissions` with RBAC (it does not replace them). Actions without `access` inherit the router's `access.resource` and the mapped CRUD verb (`instance` POST → `update`, `collection` POST → `create`). Set `access` on custom actions that must not inherit, or they follow that mapping.

MCP and SyncDB registries use TerrenoApp-injected `accessControl` (not pre-build legacy permission arrays). User `roles` on modelRouter writes are dropped when `accessControl` is set.

### Audit

`RoleManager` writes `RbacAudit` (with `permissionDelta`) on create/update/remove/assign/unassign. HTTP `rbacRouter` no longer writes a second row. Pass `auditSink` (one function or an array) to fan into an app log; `persistAudit: false` skips the built-in collection and then requires at least one sink.

Assignment **preview** does not write denied-assign rows. Denied mutation audits are stored only for the escalation `403` (`Cannot grant permissions you do not hold`).

## Admin frontend

`@terreno/admin-frontend` is now provider-backed: wrap screens in `AdminProvider`, use the widget registry / `AdminScreenRouter`, and prefer `AdminRolesField` / `AdminRolesList` over raw role arrays. The sidebar groups Scripts, Roles, Version, Audit Log, Feature Flags, and Configuration under **Platform**. Empty sections hide.

If you still pass the deprecated `customScreens` prop, migrate to the widget registry (`mergeWidgetRegistry`, `BUILT_IN_WIDGET_REGISTRY`).

## MCP on `modelRouter`

Opt a model in with `mcp` on `modelRouter`. Tools are served at `POST /mcp` with the same permissions, filters, and hooks as REST. Lifecycle hooks receive a stub request from `createMCPRequest` (`isMCPRequest: true`); they do not see forwarded HTTP headers. Register extra tools with `registerMCPTool`. `@terreno/rtk` adds `useMCPTools()` and `useTerrenoChat()`.

## Comms

Optional `SendGridMailProvider` lives at `@terreno/comms/adapters/sendgrid` (peer `@sendgrid/mail`). Phase 1 hooks: `beforeSend` may mutate or cancel; `onRetry` stays `(context, result)` with `context.attempt`. Push prune treats `errorClass: "permanent"` like `isPermanentFailure`.

## `@terreno/ui`

React Native Web `shadow*` and `props.pointerEvents` deprecation warnings are fixed inside the library. No app code change is required unless you copied those patterns locally — use `style.pointerEvents` and `boxShadow`.

`Host` and `Portal` are exported from `@terreno/ui` (replacing `react-native-portalize`).

## Verification

- Compile and lint the app against `@terreno/*@57.1.0`.
- If you imported `RbacRoleModel` as a value, switch to `createAccess` / `createRbacRoleModel`.
- If RBAC is on, confirm admin list/create still works for each model and that `admin:access`-only roles cannot mutate resources.
- Confirm signup / `PATCH /auth/me` cannot set `admin`, `roles`, or `organizationIds`.
- If you use collection RTK Query hooks, start the syncdb migration (see above).
- Regenerated OpenAPI SDK after enabling `mcp` or new admin/RBAC routes.
