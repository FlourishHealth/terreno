# 57.0.0

First stable release of the Expo SDK 57 line. Packages publish to the npm `latest`
dist-tag. Apps that are not ready to upgrade Expo should stay on the `0.x` line
(`npm install @terreno/ui@0.31.0` or your current pin).

```bash
bun add @terreno/ui @terreno/api @terreno/rtk
# optional local-first data layer
bun add @terreno/syncdb
```

## Upgrade Expo before Terreno

This line targets Expo SDK 57. Upgrade the app first, then bump `@terreno/*`:

| Package | Version |
|---------|---------|
| `expo` | `~57.0.14` |
| `react-native` | `0.86.2` |
| `react` | `19.2.3` |
| `typescript` | `~6.0.3` |

Follow Expo's SDK 57 upgrade guide, then bump `@terreno/*` to `57.0.0`.
Run `npx expo install expo@latest --fix` at the app root, rebuild native binaries, then
`bun run compile` / `bun run lint`. Regenerate the OpenAPI SDK after any `@terreno/api`
surface change (`bun run sdk` in the frontend).

Terreno's version major now tracks the Expo SDK major. There is no in-place semver path
from `0.x` or `56.x` across Expo SDK majors — treat this as an Expo upgrade plus a
Terreno major bump.

## `@terreno/syncdb` and TinyBase 9.5

`@terreno/syncdb` depends on `tinybase` `^9.5.1` for Expo SDK 57 / `expo-sqlite` type
compatibility. Apps using syncdb should reinstall and re-run sync integration tests after
upgrading Expo.

## From `57.0.0-beta.1`

If you already validated on the beta line, bump the exact version from `57.0.0-beta.1` to
`57.0.0` (or drop the `@beta` dist-tag). No additional code changes are required beyond
rebuilding native binaries if you changed Expo during the beta period.

## From `0.x` or `56.x`

Stay on your current Terreno major until the app runs on Expo SDK 57. Backend-only apps
can often stay on `0.x` longer; frontend packages (`ui`, `rtk`, `admin-frontend`,
`admin-spa`, `syncdb`) require the matching Expo major.
