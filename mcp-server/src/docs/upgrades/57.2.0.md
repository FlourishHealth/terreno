# 57.2.0

Terreno packages move in lockstep. Bump every `@terreno/*` dependency to `57.2.0`, then:

```bash
bun add @terreno/ui @terreno/api @terreno/rtk
# optional
bun add @terreno/syncdb @terreno/admin-frontend @terreno/comms
```

- `bun run compile` and `bun run lint` at the app root
- `cd <your frontend> && bun run sdk` after any `@terreno/api` route or model surface change

This is a minor on the Expo SDK 57 line. No Expo upgrade is required if you are already on `57.0.0` or `57.1.0`.

## Lifecycle stage YAML is `v: 2`

If you do not parse Grow/Pick/Roast/Brew/Taste handoff YAML in an outer loop, skip this section.

Handoff YAML is compact `v: 2`. Required keys are `v`, `stage`, `status`, `next`, and `action`. Empty keys are omitted. Chat and PRs keep the block inside a Details toggle.

Rename parsers that still read the v1 names:

| v1 | v2 |
| --- | --- |
| `schema_version` | `v` (constant `2`) |
| `recommended_next_stage` | `next` |
| `recommended_next_action` | `action` |
| `head_sha` | `sha` |
| `supporting_skills` | `skills` |
| `completed` | `done` |
| `failures` | `fail` |
| `blockers` | `block` |
| `decisions_required` | `ask` |
| `next_check_after_seconds` | `wait` |
| `last_result` | `last` |
| `attempted_approaches` | `tried` |

Grow still prints a 15-line index, then lists every grilled decision in an unbounded table (the table is omitted when there were none). It stays on a question until the answer is executable.

Schema: [`skills/1-grow/references/stage-result.schema.json`](../../../skills/1-grow/references/stage-result.schema.json).

## Bun 1.4 (contributors and CI)

Local and GitHub Actions toolchains that pinned Bun now use `1.4.0`. `@types/bun` / `bun-types` are `^1.4.0`. Apps scaffolded by `@terreno/mcp` get `@types/bun@^1.4.0`.

Install Bun 1.4 or newer before developing against this tag. EAS profile `bun` fields are unchanged so Expo fingerprints (and native runtime versions) stay the same.

## Admin RBAC

`admin:access` is the only permission that opens the admin page. `GET /admin/config` returns 403 without it. Script, configuration, RBAC, and per-model permissions never grant entry on their own.

With access control, each model uses `read` / `write` / `writeOwned`. `writeOwned` can create any new record; `isOwned` applies to update and delete. Custom screens and Platform tools are filtered per caller. List/read rows include `_adminCapabilities.update` and `_adminCapabilities.delete`.

Roles UI uses a one-select access level per model. Forms the caller cannot write stay read-only.

See [`docs/reference/admin-backend.md`](../../../docs/reference/admin-backend.md) and [`docs/reference/admin-frontend.md`](../../../docs/reference/admin-frontend.md).

## `@terreno/rtk` data sync is still deprecated

Collection CRUD through `@terreno/rtk` remains deprecated. Migrate collection screens to [`@terreno/syncdb`](../../../docs/reference/syncdb.md) using [migrate-rtk-to-syncdb.md](../../../docs/how-to/migrate-rtk-to-syncdb.md).
