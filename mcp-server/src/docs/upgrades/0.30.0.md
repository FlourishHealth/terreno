# Upgrading to 0.30.0

**Action required:** Yes
**Affected packages:** @terreno/api, @terreno/ui, @terreno/rtk, @terreno/feature-flags, @terreno/test, @terreno/ai, @terreno/admin-backend

Per-release upgrade notes were not maintained from 0.22.0 through 0.30.0. This note consolidates consumer-facing changes for **0.21.0 → 0.30.0**. It does not replace later notes (`0.31.0.md`, `56.0.0-beta.2.md`, `57.x`). If you are jumping past 0.30.0, apply this note and then the later notes in order.

OpenFeature (`GET …/evaluate` → `GET …/flagConfiguration`) shipped in 0.20.0 (`#761`) without an upgrade note. It is included here because the 0.21.0 README carried the only copy of the migration, and that section is no longer in the root README.

## Summary

Bump every `@terreno/*` package together to `0.30.0`. Most apps only need the SelectField prop rename and `APIError` field contract. Direct feature-flag HTTP clients must leave `/evaluate`. New packages (`@terreno/test`, later first publishes of `@terreno/ai` / `@terreno/admin-backend` / `@terreno/feature-flags`) are additive.

## Breaking changes

### `SelectField` `searchable` renamed to `disableSearch`

**What changed**

`@terreno/ui` `SelectField` no longer accepts `searchable`. Search is on by default. Pass `disableSearch` to turn it off. Commit `121b9b81` (`#954`, 0.28.0).

**Why**

The old default (`searchable={true}`) made “off” the thing you had to name. The new prop names the exception.

**Migration**

```tsx
// Before
<SelectField searchable options={options} value={value} onChange={onChange} />
<SelectField searchable={false} options={options} value={value} onChange={onChange} />

// After
<SelectField options={options} value={value} onChange={onChange} />
<SelectField disableSearch options={options} value={value} onChange={onChange} />
```

### `APIError` uses standard `Error` fields

**What changed**

`APIError.message` is exactly `title`. Put per-occurrence text in `detail` and wrapped errors in `cause`. Status subclasses (`NotFoundError`, `ForbiddenError`, …) exist. 0.28.0 `adde07d4` (`#949`); 0.30.0 `#967` preserves `status` / `title` / `detail` / `code` / `meta` when `modelRouter` rethrows.

**Why**

Sentry and log explorers group on `Error.message` / `name`. Concatenating `detail` into `title` split one problem type into many issues.

**Migration**

```typescript
// Before
throw new APIError({status: 400, title: `Todo ${id} failed: ${err.message}`});

// After
throw new APIError({
  status: 400,
  title: "Todo update failed",
  detail: err.message,
  cause: err,
  code: "todo-update-failed",
});
```

If you read `error.title` on the client, keep doing so for JSON:API bodies. Do not assume `message` contains `detail`.

### Feature flags: stop calling `GET …/evaluate`

**What changed**

`GET {basePath}/flagConfiguration` is the supported bulk endpoint. `GET {basePath}/evaluate` is deprecated (`Deprecation: true`, `Sunset` header). Client path: `useTerrenoFeatureFlags` plus OpenFeature React hooks. Shipped 0.20.0 `#761`; documented on the 0.21.0 README; not previously in `mcp-server/src/docs/upgrades/`.

**Why**

The payload matches OpenFeature’s static configuration shape so `@openfeature/react-sdk` can evaluate on the client without a second targeting pass.

**Migration**

Full checklist: [Migrating from GET …/evaluate](../../../docs/how-to/add-feature-flags.md#migrating-from-get-evaluate-openfeature).

```typescript
// Before — hand-written client
await fetch("/feature-flags/evaluate");

// After — OpenFeature via @terreno/rtk
import {useBooleanFlagValue} from "@openfeature/react-sdk";
import {useTerrenoFeatureFlags} from "@terreno/rtk";

useTerrenoFeatureFlags(terrenoApi, {userId, skip: !userId});
const enabled = useBooleanFlagValue("new-ui", false);
```

Install `@openfeature/react-sdk` and `@openfeature/web-sdk` in the app (peer versions from `@terreno/rtk`). Wrap readers in `<OpenFeatureProvider domain="feature-flags">`. `useFeatureFlags(terrenoApi)` still works and already uses `/flagConfiguration`.

## Deprecations

- `GET {basePath}/evaluate` on `@terreno/feature-flags` — use `/flagConfiguration` or `@terreno/rtk` hooks. See the how-to linked above.

- First npm publish of `@terreno/ai`, `@terreno/admin-backend`, `@terreno/feature-flags` at 0.22.1 (lockstep bump; `#824`).
- `OpenApiMiddlewareBuilder.withOperationId()` (0.22.0 `#815`).
- `Button` `ghost` / `sm` (0.22.0 `#816`).
- Compound UI `testID`s (0.23.0 `#832` / `#840`).
- Admin Script Runner CLI (0.23.0 `#828`).
- `createAuthenticatedClient` / `normalizeApiError` / `withApiErrorHandling` exported from `@terreno/api` (0.25.0 `api/src/index.ts` `export * from "./httpClient"`).

Example-backend seed admin email is `admin@example.com` from 0.27.0 (`#935`); password unchanged. Internal barrel `index.ts` files are banned in this repo (0.26.0 `#907`) — only a consumer issue if you copied those internals.

## Verification

- `bun add` every `@terreno/*` dependency to `0.30.0` (do not mix with 0.21.x).
- `bun run compile` and `bun run lint` at the app root.
- Search the frontend for `searchable=` on `SelectField` — there must be none.
- If you called `/feature-flags/evaluate` directly, switch to `/flagConfiguration` or `useTerrenoFeatureFlags`, then `cd <your frontend> && bun run sdk`.
- Hit an error path and confirm the JSON:API `title` is stable and `detail` holds the occurrence text.
