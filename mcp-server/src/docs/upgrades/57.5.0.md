# Upgrading to 57.5.0

**Action required:** Yes
**Affected packages:** @terreno/api, @terreno/ai, @terreno/admin-backend, @terreno/announcements, @terreno/api-health, @terreno/comms, @terreno/feature-flags, @terreno/jobs, @terreno/test, @terreno/admin-spa, @terreno/ui, @terreno/admin-frontend, @terreno/rtk, @terreno/syncdb, @terreno/mcp, @terreno/cli, create-terreno-app

## Summary

Bump every `@terreno/*` package together to `57.5.0`. This patch on the Expo SDK 57 line ships TypeScript 6 tsconfigs without `ignoreDeprecations`, adds `@terreno/cli`, SyncDB tools on `terreno-mcp-local`, and Slack user mentions by member id. No Expo upgrade is required if you are already on `57.x`.

## Changed behavior

### TypeScript 6 tsconfigs

**What changed**

Every package tsconfig builds on TypeScript 6 with no `ignoreDeprecations`. Node libraries (`@terreno/api`, `ai`, `admin-backend`, `announcements`, `api-health`, `comms`, `feature-flags`, `jobs`, `test`, and the `admin-spa` server plugin) compile with `module: nodenext` to ES2023 CommonJS. Dynamic `import()` stays a real ESM import so `loadMigrations` can load files by `file://` URL from compiled `dist/`. Frontend libraries (`ui`, `admin-frontend`, `rtk`, `syncdb`) emit ES2022 with bundler resolution and declaration maps. `@terreno/test` no longer publishes compiled Bun tests. `create-terreno-app` scaffolds drop `ignoreDeprecations` and `moduleResolution: node`, and the generated backend moves to TypeScript 6.

**Why**

TypeScript 6 rejects options that TypeScript 7 removes. `module: commonjs` rewrote dynamic `import()` to `require()`, which cannot load `file://` URLs or ESM-only code.

**Migration**

```jsonc
// Before (Node package)
{
  "compilerOptions": {
    "target": "es5",
    "module": "commonjs",
    "moduleResolution": "node",
    "ignoreDeprecations": "6.0"
  }
}

// After
{
  "compilerOptions": {
    "target": "es2023",
    "module": "nodenext",
    "moduleResolution": "nodenext"
  }
}
```

Copy the closest profile from `docs/explanation/typescript-configuration.md`. Do not set `ignoreDeprecations`, `baseUrl`, or `moduleResolution: node`.

## New capabilities

- `@terreno/cli` (`terreno`) for docs search, codegen, bootstrap, unified logs, Redux/RTK inspection, opt-in CDP, Bun 1.4 WebView automation, read-only database tools, and OpenAPI `api list|call|request`.
- `terreno-mcp-local` SyncDB inspect/snapshot/mutate tools. State-changing operations require `TERRENO_MCP_EVAL=1`.
- `sendToSlack` `mentionUserIds` plus `formatSlackUserMention`, `normalizeSlackUserId`, and `lookupSlackUserIdByEmail`.

## Verification

- `bun run compile` and `bun run lint` at the app root
- Confirm `tsconfig.json` has no `ignoreDeprecations`
- `cd <your frontend> && bun run sdk` after any `@terreno/api` route or model surface change
