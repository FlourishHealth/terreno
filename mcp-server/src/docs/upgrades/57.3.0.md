# Upgrading to 57.3.0

**Action required:** Yes
**Affected packages:** @terreno/api, @terreno/rtk, @terreno/ui, @terreno/comms, @terreno/admin-frontend, @terreno/mcp

## Summary

Bump every `@terreno/*` package together to `57.3.0`. This minor on the Expo SDK 57 line adds opt-in rate limiting, inbound webhooks, password reset / email verification, comms adapters (Twilio SMS, Twilio Verify, Expo push), a comms admin dashboard, `describeModel`, and `Popover`. Collection live updates through `modelRouter` `realtime` and `@terreno/rtk` cache-patch helpers are deprecated for removal in Terreno 58. No Expo upgrade is required if you are already on `57.x`.

## Breaking changes

None

## Deprecations

### `modelRouter` `realtime` and RTK cache-patch helpers

These still work in 57.3.0 and will be removed in Terreno **58**:

- `modelRouter` option `realtime`
- `@terreno/rtk` `realtimeList`, `realtimeDocument`, `setRealtimeSocket`, `getRealtimeSocket`

Migrate collection live updates to `sync` + `@terreno/syncdb`. Keep `RealtimeApp` registered — sync sockets still need it.

See [migrate-rtk-to-syncdb.md](../../../docs/how-to/migrate-rtk-to-syncdb.md).

## Changed behavior

### Collection registry

**What changed**

`modelRouter` stores options in one in-memory catalog keyed by route path. MCP, realtime, and sync read that catalog. `replaceCollectionOptions` updates every surface at once. Test `clear*` helpers clear the whole catalog.

**Why**

MCP, REST, and sync were drifting onto separate option copies.

**Migration**

If tests called a per-surface `clear*` helper expecting other surfaces to stay registered, re-register routers after clear. Production apps that only call `modelRouter` once per path do not need a code change.

### MCP writes use REST/Sync executors

**What changed**

MCP create, update, and delete run through `executeCreate` / `executeUpdate` / `executeDelete`. Permission denials and hook failures use `APIError` titles in the MCP error envelope. Invalid document `_id` values from `loadDocOr404` are 404, not populate `CastError`s. User-role stripping runs after hooks.

**Why**

MCP writes were a second mutation path that skipped REST/Sync permission and hook behavior.

**Migration**

```typescript
// Before: MCP tools could surface CastError on a bad _id
// After: treat invalid ids as 404 / APIError title in the MCP envelope
```

Update MCP clients that matched populate `CastError` strings. Hooks now see the same executor path as REST.

### Heavy `@terreno/ui` screens are lazy

**What changed**

`GPTChat`, `MarkdownEditor`, `ConsentFormScreen`, `AIRequestExplorer`, and the other named exports from `lazyBoundaries/heavyOptionalExports` load through lazy boundaries. Named exports are unchanged.

**Why**

A root `@terreno/ui` import pulled those screens into every bundle.

**Migration**

Keep importing the same names from `@terreno/ui`. If a test or Metro config assumed those modules loaded synchronously at import time, wait for the lazy boundary (or import the concrete file in tests).

### OpenAPI / admin / MCP field graphs come from `describeModel`

**What changed**

`getOpenApiSpecForModel`, admin `/admin/config` field metadata, and MCP Zod tool schemas format `describeModel()` instead of walking `schema.paths` separately. Map fields take their value kind from Mongoose `of` / `getEmbeddedSchemaType()` (not a date fallback).

**Why**

Three surfaces were inventing different types for the same schema.

**Migration**

Regenerate the frontend SDK (`bun run sdk`). If a Map field was typed as date in OpenAPI, expect the real value kind.

### Better Auth-only realtime

**What changed**

Realtime sockets can authenticate with Better Auth only. A legacy JWT secret is no longer required for that path.

**Migration**

Better Auth apps can omit JWT token secrets for realtime. JWT apps are unchanged.

### `oauthProvider` on email/password Better Auth users

**What changed**

Lazy User create no longer writes `oauthProvider: null` on email/password sign-up.

**Why**

`strict: "throw"` User schemas without that field returned 401 on the first authenticated request.

**Migration**

No action if the field is optional. If you queried `{oauthProvider: null}` for password users, query missing/`$in` instead.

## New capabilities

### Opt-in HTTP rate limiting

Pass `rateLimit: {}` on `TerrenoApp` (memory default; `redis` or `mongo` for shared buckets). Auth credential routes: 20 / 15 minutes. Other framework HTTP: 600 / 15 minutes. Omit `rateLimit` to leave HTTP unlimited until Terreno 58. 429 uses `APIError` `code: "rate-limit-exceeded"`. `trustProxy` defaults off (set `1` on Cloud Run). See [rate-limiting.md](../../../docs/how-to/rate-limiting.md).

### Inbound webhooks

Register `WebhooksApp` for HMAC / Stripe / Twilio / SendGrid verification, raw-body capture, and idempotency. `CommsApp` can mount Twilio status/inbound and SendGrid Event Webhook routes on the same plugin. See [inbound-webhooks.md](../../../docs/how-to/inbound-webhooks.md).

### Password reset and email verification

JWT: `POST /auth/forgotPassword` (always 202), `POST /auth/resetPassword`, `POST /auth/sendVerification`, `POST /auth/verifyEmail`. Opt in with `emailVerificationPlugin`, `tokenEpoch`, `authOptions.publicAppUrl` / `sendMail`, and `@terreno/comms` `renderAuthMail`. Better Auth uses the same `publicAppUrl` and `sendMail`. `LoginScreen` accepts `onForgotPassword`. See [password-reset.md](../../../docs/how-to/password-reset.md).

### Comms adapters and admin dashboard

Optional peers: `TwilioSmsProvider` (`@terreno/comms/adapters/twilioSms`), `TwilioVerifyProvider` (`@terreno/comms/adapters/twilioVerify`), `ExpoPushProvider` (`@terreno/comms/adapters/expoPush`). Admin comms screens in `@terreno/admin-frontend` list delivery logs, retry, and provider failure rates.

### `describeModel` and `Popover`

`describeModel` / `describeModelForRouter` plus OpenAPI/admin/Zod converters are public in `@terreno/api`. `Popover` is new in `@terreno/ui`.

### MCP docs `version`

`terreno_search_docs` and `terreno_get_component_docs` accept `version` to search retained docs snapshots.

## Verification

- `bun add` every `@terreno/*` dependency to `57.3.0`, then `bun run compile` and `bun run lint` at the app root
- `cd <your frontend> && bun run sdk` after pulling `@terreno/api` (schema metadata and new auth routes)
- If you still pass `realtime` on `modelRouter` or use RTK `realtimeList` / `realtimeDocument`, start the syncdb migration before Terreno 58
- If you enable `rateLimit`, confirm login 429s after 20 attempts / 15 minutes and that Cloud Run sets `trustProxy: 1`
- If you add password reset, follow [password-reset.md](../../../docs/how-to/password-reset.md) and confirm forgot-password always returns 202
