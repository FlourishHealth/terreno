# Public roadmap process

## Maintainer setup

GitHub Discussions must be enabled before its categories can be configured:

**Path:** Settings → General → Features → Discussions

1. Open the repository's **Settings**.
2. Under **General → Features**, enable **Discussions**.
3. Open **Discussions → Categories** and create the categories below in the
   listed display order.

| Order | Category | Format | Description |
|-------|----------|--------|-------------|
| 1 | Announcements | Announcement | Official Terreno releases, breaking changes, deprecations, and project news. Only maintainers can create posts; everyone can read and reply. |
| 2 | Q&A | Question / Answer | Ask for help building with Terreno and mark the response that solves your problem. Search existing questions and the documentation before posting. |
| 3 | Ideas | Open-ended | Share a problem or feature idea that could improve Terreno. This is the public intake funnel; maintainers promote shaped and actionable ideas to GitHub issues. |
| 4 | Agents & AI | Open-ended | Discuss Terreno's MCP server, coding-agent skills, AI workflows, and prompt patterns. Share setup questions, working techniques, and agent-related feedback here. |
| 5 | RFCs | Open-ended | Propose a significant public API change or a new package for community review. Accepted RFCs graduate into an implementation plan before development begins. |
| 6 | Show and tell | Open-ended | Show applications, integrations, and experiments built with Terreno. Include what you built, how Terreno helped, and any lessons other builders can reuse. |
| 7 | Docs feedback | Open-ended | Report unclear, missing, or outdated documentation and suggest improvements. Include the page URL so maintainers can route the feedback quickly. |

Keep **Announcements** restricted to maintainer-created posts. The remaining
categories accept posts from any GitHub user, with moderation applied after
posting.
